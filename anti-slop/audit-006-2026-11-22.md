### 1. [HIGH] Bottleneck Latensi SSR & Thundering Herd: Query Waterfall Berurutan & Ketiadaan In-Flight Deduplication (SingleFlight SWR)
- **Lokasi**: [index.astro](file:///media/rasyiqi/7653717A1C07B131/mamasar/src/client/pages/index.astro#L35-L82), [cache.ts](file:///media/rasyiqi/7653717A1C07B131/mamasar/src/lib/cache.ts#L9-L29), [Layout.astro](file:///media/rasyiqi/7653717A1C07B131/mamasar/src/client/layouts/Layout.astro#L40-L43)
- **Pelanggaran**: `my-skill` Pillar IV (SingleFlight SWR Cache & TTFB < 200ms) & Anti-Slop `R-40` (Performance Mechanisms).
- **Detail**:
  - Pada `index.astro`, terdapat 7 hingga 9 query database Neon (HTTP serverless driver) yang dieksekusi secara serial (`await` beruntun): `getAllZones()`, `getAllUMKM()`, `getArticles()`, `getProductsCount()`, `getProducts()`, `getProducts(spotlight)`, `getMostFavoritedProducts()`, `resolveUser()`, dan `getUserFavoriteIds()`. Ditambah lagi, `Layout.astro` yang membungkus halaman mengeksekusi `getAllZones()` dan `resolveUser()` lagi secara terpisah.
  - Setiap query HTTP Neon membutuhkan round-trip jaringan (~50–120ms). Menjalankannya secara beruntun membuat TTFB (Time to First Byte) membengkak 400ms – 1.000ms+ sebelum browser menerima byte pertama HTML.
  - Implementasi cache di `cache.ts` hanyalah `Map` memori sederhana tanpa *SingleFlight promise coalescing*. Ketika cache kedaluwarsa atau terjadi cold-start pada traffic bersamaan (misal 20 request serentak), seluruh request akan memicu `loader()` secara bersamaan (thundering herd/cache stampede), membanjiri koneksi database serverless Neon.
- **Solusi**:
  - Paralelkan query independen menggunakan `Promise.all([ ... ])` di `index.astro`.
  - Implementasikan pola SingleFlight di `cache.ts` dengan menyimpan `inFlightPromises = new Map<string, Promise<T>>()` sehingga request paralel pada key yang sama menumpang pada satu promise yang sedang berjalan.

### 2. [HIGH] Redundant Database Auth Lookups: Ketiadaan Penyimpanan `Astro.locals.user` Menyebabkan 2–3x Query Sesi per Request
- **Lokasi**: [middleware.ts](file:///media/rasyiqi/7653717A1C07B131/mamasar/src/client/middleware.ts#L8), [Layout.astro](file:///media/rasyiqi/7653717A1C07B131/mamasar/src/client/layouts/Layout.astro#L43), [index.astro](file:///media/rasyiqi/7653717A1C07B131/mamasar/src/client/pages/index.astro#L80), [dashboard/index.astro](file:///media/rasyiqi/7653717A1C07B131/mamasar/src/client/pages/dashboard/index.astro#L6)
- **Pelanggaran**: `my-skill` Pillar I & IV (Hemat Resource CPU/DB & Anti-Redundant Roundtrips).
- **Detail**:
  - Pada Astro SSR, `middleware.ts` memeriksa otentikasi user dengan `await resolveUser(context.request)`. Namun hasilnya tidak pernah disimpan di `context.locals.user`.
  - Akibatnya, ketika request diteruskan ke halaman (misalnya `/dashboard/index.astro`), halaman tersebut memanggil `await resolveUser(Astro.request)` kembali. Kemudian komponen `Layout.astro` yang dirender di dalamnya kembali memanggil `await resolveUser(Astro.request)`.
  - Fungsi `resolveUser()` mengeksekusi `getUserFromSession()` yang melakukan `SELECT ... FROM sessions JOIN users LEFT JOIN umkm LEFT JOIN zones WHERE sessions.id = ...`.
  - Dalam satu request navigasi dashboard atau beranda berotentikasi, query sesi yang sama persis dikirim ke database Neon sebanyak 2 hingga 3 kali berturut-turut!
- **Solusi**:
  - Resolusi user sekali saja di `middleware.ts` dan simpan ke `context.locals.user`.
  - Jadikan `Astro.locals.user` sebagai sumber tunggal kebenaran (single source of truth) untuk seluruh komponen halaman dan layout.

### 3. [HIGH] Missing Critical Database Indexes pada Tabel Inti (`products`, `umkm`, `sessions`)
- **Lokasi**: [schema.ts](file:///media/rasyiqi/7653717A1C07B131/mamasar/src/lib/schema.ts#L83-L105), [migrate-neon.js](file:///media/rasyiqi/7653717A1C07B131/mamasar/scripts/migrate-neon.js#L71-L128)
- **Pelanggaran**: `my-skill` Pillar I (DB Indexed Columns) & Pillar IV (Resource Hygiene).
- **Detail**:
  - Tabel `products` hanya memiliki primary key `id` dan unique `slug`. Kolom-kolom kunci yang di-query, di-filter, dan di-join pada setiap halaman katalog tidak memiliki index:
    - `umkm_id` (foreign key dan filter toko).
    - `category` (filter kategori produk).
    - `bumped_at` & `created_at` (sorting utama `lastBumpedFirst`).
    - `is_featured` & `featured_until` (kondisional sorting produk unggulan).
  - Tabel `umkm` tidak memiliki index pada `zone_id`.
  - Tabel `sessions` tidak memiliki index pada `expires_at` (yang dicek dalam pembersihan sesi).
  - Setiap pencarian atau filter produk di database menyebabkan PostgreSQL melakukan full table scan. Seiring bertambahnya produk, pemakaian CPU database akan melonjak tajam dan waktu eksekusi query melambat drastis.
- **Solusi**:
  - Tambahkan index eksplisit di `schema.ts` dan `migrate-neon.js`:
    - `index('idx_products_umkm').on(t.umkm_id)`
    - `index('idx_products_category').on(t.category)`
    - `index('idx_products_bumped').on(t.bumped_at.desc(), t.created_at.desc())`
    - `index('idx_umkm_zone').on(t.zone_id)`
    - `index('idx_sessions_expires').on(t.expires_at)`

### 5. [HIGH] Service Worker Cache Leaks: Penyimpanan Halaman HTML Privat Terotentikasi (`/dashboard`, `/admin`) ke dalam Public Cache Storage
- **Lokasi**: [sw.js](file:///media/rasyiqi/7653717A1C07B131/mamasar/public/sw.js#L62-L73)
- **Pelanggaran**: `my-skill` Pillar III (Security by Default) & Pillar IV (Resource Hygiene).
- **Detail**:
  - Pada `sw.js` baris 62–73 (Strategi A: Navigasi HTML):
    ```js
    if (request.mode === 'navigate') {
      event.respondWith(
        fetch(request)
          .then((networkResponse) => {
            if (networkResponse && networkResponse.status === 200) {
              const responseClone = networkResponse.clone();
              caches.open(CACHE_NAME).then((cache) => {
                cache.put(request, responseClone);
              });
            }
            return networkResponse;
          })
          ...
      );
    }
    ```
  - Pengecualian hanya ada untuk `/api/` dan `/uploads/` (baris 57).
  - Halaman sensitif dan dinamis seperti `/dashboard`, `/dashboard/*`, `/admin`, `/admin/*`, dan `/login` ikut disimpan ke dalam `CacheStorage` browser.
  - Ketika perangkat sedang offline atau koneksi lambat, Service Worker akan menyajikan cache HTML lama dari sesi sebelumnya. Jika perangkat digunakan bersama, data dashboard toko akun sebelumnya dapat terlihat di layar. Selain itu, penyimpanan HTML dynamic ini memakan kuota disk CacheStorage browser secara percuma.
- **Solusi**: Tambahkan pengecualian rute terotentikasi di `sw.js`:
  ```js
  if (
    url.pathname.startsWith('/api/') ||
    url.pathname.startsWith('/uploads/') ||
    url.pathname.startsWith('/dashboard') ||
    url.pathname.startsWith('/admin') ||
    url.pathname.startsWith('/login')
  ) {
    return; // Biarkan network-only
  }
  ```

### 6. [MEDIUM] LCP Degradation: Lazy-Loading pada Gambar Spotlight Pertama Above/Near-the-Fold
- **Lokasi**: [index.astro](file:///media/rasyiqi/7653717A1C07B131/mamasar/src/client/pages/index.astro#L248), [ProductCard.astro](file:///media/rasyiqi/7653717A1C07B131/mamasar/src/client/components/ProductCard.astro#L113)
- **Pelanggaran**: `my-skill` Pillar IV (Core Web Vitals LCP < 1.2s) & Anti-Slop `R-40` (Performance Mechanisms: "hero image is an img in the HTML, never loading=lazy, with fetchpriority=high").
- **Detail**:
  - Di beranda `index.astro`, tepat di bawah filter pencarian terdapat seksi "Pilihan Unggulan Hari Ini" (Spotlight). Pada layar desktop dan perangkat seluler berlayar besar, kartu pertama produk unggulan ini berada langsung di viewport (above-the-fold atau near-the-fold) dan menjadi elemen konten visual terbesar (Largest Contentful Paint).
  - Namun di `ProductCard.astro` baris 113, tag `<img>` produk selalu menggunakan atribut statis `loading="lazy"`.
  - Akibatnya, peramban sengaja menunda pengunduhan gambar kartu pertama sampai engine peramban selesai menghitung tata letak, sehingga LCP melonjak lambat (bisa $> 2.0\text{s}$ pada jaringan seluler 4G/3G).
- **Solusi**:
  - Berikan prop opsional `loading?: 'lazy' | 'eager'` dan `fetchPriority?: 'high' | 'auto' | 'low'` pada `ProductCard.astro`.
  - Untuk kartu spotlight pertama (`idx === 0`), berikan `loading="eager"` dan `fetchpriority="high"`.

### 7. [MEDIUM] Over-fetching & Database Payload Bloat pada Beranda (`getAllUMKM()` & `getArticles()`)
- **Lokasi**: [index.astro](file:///media/rasyiqi/7653717A1C07B131/mamasar/src/client/pages/index.astro#L36-L37), [stores.ts](file:///media/rasyiqi/7653717A1C07B131/mamasar/src/lib/modules/stores.ts#L74-L98), [articles.ts](file:///media/rasyiqi/7653717A1C07B131/mamasar/src/lib/modules/articles.ts#L20-L23)
- **Pelanggaran**: `my-skill` Pillar I & IV (Hemat RAM VPS, Data Transfer Bloat, TTFB).
- **Detail**:
  - Di `index.astro` baris 36: `const sellers = await getAllUMKM();`. Fungsi ini melakukan query agregasi seluruh tabel UMKM + string_agg gambar produk dari seluruh pedagang di database, lalu melakukan `resolveAvatarUrl` untuk setiap baris, padahal beranda hanya menampilkan **4 toko** teratas (`verifiedSellers.slice(0, 4)` pada baris 378).
  - Di `index.astro` baris 37: `const articles = await getArticles();`. Fungsi ini melakukan `SELECT * FROM articles` yang menarik seluruh kolom `content` (bisa puluhan kilobyte teks artikel lengkap per artikel) tanpa cache memori, padahal beranda hanya membutuhkan 3 artikel dengan ringkasan pendek (`summary`).
  - Hal ini membebani memori proses Node/Bun dan menghabiskan bandwidth jaringan database serverless.
- **Solusi**:
  - Gunakan query khusus beranda: `getFeaturedStores(4)` dengan klausa `LIMIT 4` dan query count terpisah yang ringan jika hanya butuh total toko.
  - Di `articles.ts`, tambahkan `getOrSetCache('articles:all', 120_000, ...)` dan buat fungsi `getRecentArticles(3)` yang hanya memilih kolom yang diperlukan (`id, title, slug, image_url, summary`).

### 8. [MEDIUM] Bundling Monolitik Pustaka Peta: Leaflet (151KB JS + 16KB CSS) Tidak Di-Lazy-Load di Panel Admin
- **Lokasi**: [ZonesPanel.astro](file:///media/rasyiqi/7653717A1C07B131/mamasar/src/client/components/admin/ZonesPanel.astro#L403-L404)
- **Pelanggaran**: `my-skill` Pillar IV (Asset Pipeline & Code Splitting) & Anti-Slop `R-40`.
- **Detail**:
  - Di `ZonesPanel.astro`, pustaka `leaflet` diimpor secara statis:
    ```ts
    import L from 'leaflet';
    import 'leaflet/dist/leaflet.css';
    ```
  - Hal ini menyebabkan bundler Vite memasukkan seluruh pustaka Leaflet ke dalam chunk klien admin (`ZonesPanel.astro...BjPq0BOd.js` berukuran 151KB dan CSS 16KB).
  - Admin yang membuka `/admin` hanya untuk memeriksa verifikasi toko, artikel, atau pendaftaran agen tetap terpaksa mengunduh dan mengeksekusi 151KB skrip peta, meskipun tab Peta Wilayah tidak pernah diklik.
- **Solusi**:
  - Ubah impor statis Leaflet menjadi *dynamic import* (`const L = await import('leaflet')`) yang baru dieksekusi saat container peta masuk viewport (IntersectionObserver) atau saat tab Wilayah diaktifkan.

### 9. [MEDIUM] SSR Blocking Latency & Redundant Query pada Halaman Detail Produk (`produk/[slug].astro`)
- **Lokasi**: [produk/[slug].astro](file:///media/rasyiqi/7653717A1C07B131/mamasar/src/client/pages/produk/[slug].astro#L43), [produk/[slug].astro](file:///media/rasyiqi/7653717A1C07B131/mamasar/src/client/pages/produk/[slug].astro#L87-L96), [produk/[slug].astro](file:///media/rasyiqi/7653717A1C07B131/mamasar/src/client/pages/produk/[slug].astro#L776)
- **Pelanggaran**: `my-skill` Pillar IV (TTFB Optimization & Eliminasi Render-Blocking Operations).
- **Detail**:
  - Di baris 43: `await incrementProductViews(product.slug);` dieksekusi langsung di jalur render SSR. Render HTML ditahan menunggu mutasi `UPDATE` database Neon selesai. Padahal view count bisa di-fire-and-forget atau didelegasikan via API klien / background task.
  - Di baris 87–96: Pencarian produk terkait menjalankan `getProducts({ category: ..., limit: 12 })`. Kemudian secara membabi-buta menjalankan query kedua `getProducts({ limit: 16 })` untuk backfill, bahkan ketika query pertama sudah mengembalikan 12 produk penuh! Ini memboroskan 1 query database Neon tambahan di setiap kali halaman produk dibuka.
  - Di baris 776: Tag `<img src={qrCodeUrl} ... loading="eager" />` memuat gambar QR code dari domain pihak ketiga `https://api.qrserver.com/...` dengan prioritas `eager`, padahal QR code tersebut terletak di bawah lipatan layar / dalam modal bagi.
- **Solusi**:
  - Jadikan `incrementProductViews` non-blocking (fire and forget) atau lewat microtask.
  - Hanya jalankan query `backfill` jika `sameCategory.length < 12`.
  - Ubah gambar QR code menjadi `loading="lazy"` atau buat secara client-side/SVG murni tanpa dependensi HTTP eksternal.

### 10. [LOW] N+1 Network Flooding pada Fitur Kosongkan Favorit (`favorit.astro`)
- **Lokasi**: [favorit.astro](file:///media/rasyiqi/7653717A1C07B131/mamasar/src/client/pages/favorit.astro#L424-L435), [favorites.ts](file:///media/rasyiqi/7653717A1C07B131/mamasar/src/server/routes/favorites.ts)
- **Pelanggaran**: `my-skill` Pillar I & IV (Atomic Operations, Network Efficiency, Anti-Chatty APIs).
- **Detail**:
  - Ketika pengguna mengklik "Kosongkan Daftar Favorit", skrip di `favorit.astro` menjalankan perulangan `for (const card of cards)` dan menembak `fetch('/api/favorites/toggle')` satu per satu untuk setiap produk.
  - Jika ada 20 produk favorit, browser akan mengirimkan 20 request HTTP terpisah secara beruntun ke server, dan server menjalankan 20 transaksi `DELETE` terpisah.

  - Sediakan endpoint tunggal `POST /api/favorites/clear` yang mengeksekusi `DELETE FROM favorites WHERE user_id = $1` secara atomik dalam satu query.

### 11. [LOW] Ketiadaan Header Caching Aset Statis & Public Images di Vercel/Node Server
- **Lokasi**: [middleware.ts](file:///media/rasyiqi/7653717A1C07B131/mamasar/src/client/middleware.ts#L17-L50), [vercel.json](file:///media/rasyiqi/7653717A1C07B131/mamasar/vercel.json)
- **Pelanggaran**: `my-skill` Pillar IV (Asset Pipeline & Cache Headers) & Anti-Slop `R-40`.
- **Detail**:
  - Di `middleware.ts`, header keamanan (`X-Content-Type-Options`, `CSP`, dll.) dipasang, namun tidak ada manajemen header `Cache-Control` untuk respons statis atau semi-statis.
  - File aset publik di root (`/favicon.svg`, `/icon-192.png`, `/manifest.webmanifest`, `/og-image.jpg` 101KB) dan konfigurasi `vercel.json` tidak mendefinisikan rules caching CDN edge (`Cache-Control: public, max-age=...`).

- **Solusi**:
  - Konfigurasikan headers caching di `vercel.json` untuk aset di `public/` dan folder `_astro/` (`public, max-age=31536000, immutable`).
